# API flow

1. `POST /auth/login` возвращает JWT.
2. `GET /composters` возвращает точки карты.
3. `POST /composters/{id}/proximity-challenge` создаёт одноразовую подписанную команду `PROVE`.
4. Android передаёт команду ближайшей ESP32 по BLE и получает подписанный ответ `PROXIMITY_CONFIRMED`.
5. `POST /composters/{id}/access` принимает координаты, идентификатор challenge и ответ устройства; сервер проверяет расстояние, срок действия, одноразовость и HMAC до создания сессии и команды `OPEN`.
6. `POST /sessions/{id}/ack` принимает подписанный результат ESP32. Неподписанные успешные ответы и ответы с неверным состоянием отклоняются.
7. `POST /sessions/{id}/photo` загружает изображение, создаёт review и возвращает `CLOSE`.
8. Пользовательский `POST /composters/{id}/incidents` использует тот же proximity proof; сотрудник может создать инцидент без пользовательского proof.
9. `GET /moderation/reviews` и `POST /moderation/reviews/{id}` реализуют ручную модерацию. Изменяемые записи блокируются транзакционно, чтобы исключить двойную обработку.

Challenge живёт ограниченное время и расходуется ровно один раз. ESP32 сохраняет использованные идентификаторы команд в NVS, поэтому повтор команды блокируется и после перезагрузки.
