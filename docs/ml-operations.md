# ML-контур определения загрязнений

## Что реализовано

Текущий `color-heuristic-v1` остаётся безопасным fallback до появления достаточного датасета. Он не считается обученной моделью. Новый контур обучает одноклассовый детектор `contamination` по решениям модераторов:

- `APPROVED` — чистое фото без объектов;
- `REJECTED` с прямоугольниками — фото загрязнения и bounding boxes;
- `REJECTED` без прямоугольников сохраняется в реестре, но исключается из обучения детектора как противоречивая разметка.

Версия датасета содержит пользователя, компостер и время съёмки. Разделение `train/val/test` выполняется целыми компостерами, поэтому почти одинаковые сцены одного бака не попадают одновременно в обучение и проверку.

## Еженедельный цикл

1. Модераторы в течение недели проверяют фото и обводят все загрязнения.
2. Администратор открывает `/web/ml` и нажимает **«Загрузить последние собранные данные»**.
3. Веб фиксирует неизменяемый `dataset-vN` и показывает баланс классов и готовность.
4. После достижения стартовых порогов администратор нажимает **«Запустить обучение»**.
5. Фоновый worker экспортирует фото из MinIO в YOLO-формат, обучает модель, считает image-level recall и долю ложных тревог на чистых фото.
6. Кандидат получает `PASSED` только при recall загрязнений не ниже 90% и false-positive rate не выше 10%.
7. Администратор вручную нажимает **«Опубликовать»**. ML-service подхватывает ONNX-модель; до этого продолжает работать fallback.

Чтобы очередь из веба обрабатывалась, worker один раз запускают вместе с окружением:

```bash
docker compose --profile training up -d ml-trainer
```

Для настоящего еженедельного режима достаточно оставить worker запущенным: новые обучения создаются кнопкой в вебе. Автоматически публиковать модель нельзя — выпуск требует проверки метрик и ошибок человеком.

## Артефакты

- `ml/runs/<run-id>/model.pt` — checkpoint обучения;
- `ml/runs/<run-id>/model.onnx` — кандидат для CPU inference;
- `ml/runs/<run-id>/report.json` — пороги и измеренные метрики;
- `ml/active/*` — явно опубликованная версия.

## Практические правила сбора

- снимать весь слой компоста, а не только подозрительный объект;
- собирать разные освещение, сезоны, телефоны и компостеры;
- обводить каждый посторонний объект плотно, но не захватывать большую область фона;
- не размечать человека, плату ESP или тестовый стол как «компост» — такие фото нужно исключать;
- регулярно проверять ошибки модели и добавлять их в следующую итерацию;
- перед пилотом держать отдельный тест на новых компостерах, который никогда не участвует в подборе порогов.

## Лицензия

Тренировочный worker использует пакет Ultralytics. Для полностью открытого проекта применим AGPL-3.0; для закрытого или коммерческого использования необходимо отдельно проверить условия и при необходимости получить коммерческую лицензию либо заменить backend обучения на модель с подходящей лицензией.
