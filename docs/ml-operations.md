# ML-контур определения загрязнений

## Что реализовано

Текущий `color-heuristic-v1` остаётся безопасным fallback до появления достаточного датасета. Он не считается обученной моделью. Новый контур обучает одноклассовый детектор `contamination` по выбранным администратором фотографиям:

- `CLEAN` — чистое разрешённое учебное фото без объектов;
- `CONTAMINATION` — разрешённое учебное фото с bounding boxes.

В список кандидатов входят ручные ML-загрузки и фотографии с завершённой модерацией. Ожидающие проверки фото не показываются. Модерированная фотография попадает в версию только после явного выбора администратором; идентификатор пользователя в manifest не сохраняется. Разделение `train/val/test` выполняется целыми источниками или компостерами, поэтому связанные серии не попадают одновременно в обучение и проверку. Версии старых схем блокируются worker и веб-маршрутом обучения.

## Еженедельный цикл

1. Администратор открывает `/web/ml/dataset-create`. Создание датасета вынесено с основного ML-экрана на отдельную страницу.
2. В списке как в почте администратор проверяет ручные загрузки и прошедшие модерацию фото: по умолчанию показаны и отмечены ещё не использованные примеры. Фильтры позволяют открыть все, только модерированные, уже использованные или убранные фото; массовые кнопки отмечают видимые строки или снимают выбор.
3. Неподходящие фото можно мягко **убрать** из будущих версий и позднее восстановить. Уже зафиксированные версии датасета при этом не меняются.
4. Администратор нажимает **«Создать версию из выбранных»**.
5. Веб фиксирует неизменяемый `dataset-vN` и показывает баланс классов и готовность.
6. После достижения стартовых порогов администратор нажимает **«Запустить обучение»**.
7. При первом запуске worker скачивает официальную разметку TACO, сводит категории мусора в `contamination` и создаёт промежуточные веса. Кэш TACO и веса сохраняются в Docker volume.
8. Worker экспортирует выбранные ручные и модерированные фотографии из MinIO в YOLO-формат, дообучает TACO-веса и считает image-level recall и долю ложных тревог на независимой test-части.
9. Кандидат нельзя публиковать, пока test-набор не содержит минимум 20 чистых и 20 загрязнённых фотографий как минимум из трёх источников. `PASSED` требует не только recall не ниже 90% и false-positive rate не выше 10%, но и прохождения соответствующих Wilson confidence bounds. Это не позволяет маленькому удачному тесту выглядеть достоверной моделью.
10. Администратор вручную нажимает **«Опубликовать»**. ML-service подхватывает ONNX-модель; до этого продолжает работать fallback.

Worker запускается вместе с окружением:

```bash
docker compose up -d ml-trainer
```

Для отдельной подготовки TACO без запуска локального обучения:

```bash
docker compose run --rm ml-trainer python -m tools.taco_pretrain prepare
```

Автоматический этап можно отключить через `ML_TACO_PRETRAIN=false`. Внешний датасет используется только для переноса признаков; val/test ComPost не смешиваются с TACO и остаются критерием публикации.

Для настоящего еженедельного режима достаточно оставить worker запущенным: новые обучения создаются кнопкой в вебе. Автоматически публиковать модель нельзя — выпуск требует проверки метрик и ошибок человеком.

## Артефакты

- `ml/runs/<run-id>/model.pt` — checkpoint обучения;
- `ml/runs/<run-id>/model.onnx` — кандидат для CPU inference;
- `ml/runs/<run-id>/report.json` — пороги и измеренные метрики;
- `ml/active/*` — явно опубликованная версия.

## Практические правила сбора

- снимать весь слой компоста, а не только подозрительный объект;
- собирать разные освещение, сезоны, телефоны и компостеры;
- обводить каждый посторонний объект плотно, но не захватывать большую область фона;
- не размечать человека, плату ESP или тестовый стол как «компост» — такие фото нужно исключать;
- регулярно проверять ошибки модели и добавлять их в следующую итерацию;
- перед пилотом держать отдельный тест на новых компостерах, который никогда не участвует в подборе порогов.

## Лицензия

Тренировочный worker использует пакет Ultralytics. Для полностью открытого проекта применим AGPL-3.0; для закрытого или коммерческого использования необходимо отдельно проверить условия и при необходимости получить коммерческую лицензию либо заменить backend обучения на модель с подходящей лицензией.
