# Модель безопасности

У каждого компостера есть отдельный 256-битный секрет на ESP32 и backend. Сервер подписывает HMAC-SHA256 канонический JSON с `commandId`, `composterId`, `sessionId`, действием, сроком и случайным `nonce`. Android не знает секрет и служит только транспортом.

ESP32 проверяет версию, устройство, HMAC, действие, срок и отсутствие `commandId`/`nonce` в replay-кэше. Срок команды — 60 секунд. Идентификаторы принятых команд и максимальный `issued_at` сохраняются в NVS, поэтому повтор блокируется после перезагрузки. При первой принятой команде устройство допускает ограниченную синхронизацию Unix-времени; после неё использует монотонный таймер. Для production требуется защищённая выдача секрета, secure boot и flash encryption.

Успешный ответ ESP32 подписывает тот же индивидуальный секрет. Сервер проверяет HMAC, `device_id`, состояние и ожидаемое действие до ACK. Пользовательский доступ и инцидент дополнительно требуют координаты в радиусе 50 метров и одноразовый challenge `PROVE`; proof расходуется транзакционно и не двигает замок.

JWT выдаёт backend после проверки PBKDF2-хеша пароля. Роли проверяются сервером; наличие BLE-соединения не даёт полномочий. Секреты из `docker-compose.yml` предназначены только для локальной разработки.
